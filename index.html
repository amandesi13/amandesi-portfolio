01 — Approach

What carrier-grade R&D actually teaches you.

Mostly humility. Usually at 3 a.m.

  1. The bug is never where the ticket says it is.

    Ticket blames the data plane. Data plane blames the hardware. Hardware replies that it works fine on its board. The faults that reached me at Nokia lived in the gaps between subsystems — often a config someone set years ago that everyone since had been too polite to touch. So I follow them through logs, traces and packet captures until something confesses. The first plausible story is not a root cause; it's just the first story.

  2. If a system can't explain itself, I don't believe it.

    “It’s probably fine” is not a metric. I build the endpoints, dashboards and detection that make a system say out loud what it’s actually doing — currently live RAN metrics on 5G testbeds, where “probably fine” can mean a cell quietly shedding throughput while everyone sleeps soundly.

  3. Research is lovely. The release still ships.

    I've owned a third-party data-plane integration end to end on a live product line: integration plan, QoS and interface validation, release evidence, and the deployment doc other teams later quoted back at me. Deadlines remain deeply unimpressed by how interesting the problem is.
